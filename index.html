Enterprise knowledge & AI

A shared foundation
for enterprise knowledge.

Designed a reusable knowledge-management template for document extraction, internal knowledge search, and termsheet comparison. Adopted as the account standard, it has also been used by another team to implement contract-field extraction.

The template combines OCR for scanned documents, adaptive field extraction, and built-in authentication. Teams can tailor its modules and extraction schemas to their use case, while developers can access enterprise knowledge through controlled MCP integrations.

  • Python
  • RAG
  • LangGraph
  • MCP
Implementation notes +

Adaptive extraction uses LangGraph and LangChain to build schema-driven retrieval queries for each requested field. It retrieves relevant chunks from ChromaDB, reranks them by similarity, and constructs an LLM prompt with source material. Results include the field value, supporting context, page number, and model-reported confidence. Subsequent retrieval passes target only unresolved fields, keeping repeated context and unnecessary model input down.

Vertical slice architecture keeps ingestion modules independently removable; environment variables can disable modules such as Jira ingestion. The template supports enterprise authentication through Kerberos and JWT-based API keys. Its MCP integration makes knowledge available in Claude Code and Copilot CLI, with group-based authorisation and time-limited credentials.

Extraction that follows the missing fields

Retrieves and reranks source chunks for the requested schema, then returns field values with context, page references, and confidence. Further passes focus on fields still missing.

Reusable presets or on-demand schemas

Teams can extend predefined extraction presets or define field names, data types, validation rules, and examples on the fly to try a new document use case.

Modules teams can tailor

Teams can disable or remove ingestion modules without carrying unnecessary functionality. The modular design includes OCR for scanned documents and built-in authentication.

infrastructure dashboard.

An infrastructure dashboard gave stakeholders valuable visibility into their applications, but its underlying design was difficult to maintain and prepare for production.

I reviewed the Python and React codebase and defined a phased modernisation plan. The restructured backend and React application are now deployed on Rancher. Work continues on a scheduled data pipeline and database-backed storage.

  • Architecture review
  • Python / React
  • REST APIs

Implementation notes +

After reviewing the codebase with its developer, I broke the work into phases: separate frontend and backend responsibilities, restructure the Python code, remove spreadsheet dependencies, and replace direct consumption of generated JSON files with REST endpoints. AI adoption & production delivery

AI adoption and
production delivery.

An existing PDF clause-extraction application had a Python RAG backend and React interface, but needed substantial code and deployment improvements before it could run reliably in production.

I modernised the codebase, resolved deployment issues, and established a repeatable build and release process. This included adapting document processing and model delivery to the firm’s environment. The application was successfully deployed on Rancher and has run reliably in production for about a year.

  • Python / React
  • RAG
  • Rancher
Implementation notes +

The Python RAG service uses Tesseract OCR and FAISS. I adapted OCR for Linux and moved the application onto GitLab CI. Because Hugging Face was blocked, I packaged the embedding model from Nexus into the application container. These changes addressed application and environment issues that were preventing production deployment.

Migration tooling & prototypes

Informatica to Python/Prefect

Built a migration plugin that takes Informatica workflows from discovery and assessment to equivalent Python/Prefect code. It supports application-wide planning and retains progress across runs.

  • Informatica
  • Python / Prefect
  • Code generation
Implementation notes +

The plugin separates discovery, assessment and code generation into focused skills. Discovery accepts manual evidence or Informatica XML exports and records missing behaviour and unresolved references. Assessment examines complexity and commonality across workflows. Generated code follows the firm’s Python project structure and AutoSys, Rancher and Prefect conventions. Each skill’s progress is tracked in JSON so the process can continue across runs.

The discovery step keeps extracted metadata, assumptions and missing runtime details explicit. Parameter files, scheduler details, production run history and SME notes provide additional context when available for downstream assessment and code generation.
