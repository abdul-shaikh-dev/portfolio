Enterprise knowledge & AI

A shared foundation
for enterprise knowledge.

Designed a reusable knowledge-management template for document extraction, internal knowledge search, and termsheet comparison. Adopted as the account standard, it has also been used by another team to implement contract-field extraction.

The template combines OCR for scanned documents, adaptive field extraction, and built-in authentication. Teams can tailor its modules and extraction schemas to their use case, while developers can access enterprise knowledge through controlled MCP integrations.

  • Python
  • LangGraph / LangChain
  • Tesseract OCR
  • ChromaDB
  • MCP
Implementation notes +

Adaptive extraction uses LangGraph and LangChain to build schema-driven retrieval queries for each requested field. It retrieves relevant chunks from ChromaDB, reranks them by similarity, and constructs an LLM prompt with source material. Results include the field value, supporting context, page number, and model-reported confidence. Subsequent retrieval passes target only unresolved fields, keeping repeated context and unnecessary model input down.

Built-in authentication supports Kerberos and JWT-based API keys. The MCP integration supports Claude Code and Copilot CLI; the knowledge service checks required Swarm-group membership before issuing a JWT-based key with a 30-day expiry.

Extraction that follows the missing fields

Retrieves and reranks source chunks for the requested schema, then returns field values with context, page references, and confidence. Further passes focus on fields still missing.

Reusable presets or on-demand schemas

Teams can extend predefined extraction presets or define field names, data types, validation rules, and examples on the fly to try a new document use case.

Modules teams can tailor

Vertical slice architecture lets teams disable modules such as Jira ingestion through environment variables, or remove them entirely. Tesseract OCR supports scanned documents, with authentication built into the template.

Recognised in the CIO newsletter in 2026 for the knowledge-management template, which another team adopted for contract-field extraction.

Application modernisation

Modernising an
infrastructure dashboard.

A dashboard gave stakeholders useful visibility into application infrastructure, but its tightly coupled Python script, spreadsheet dependencies, and file-based data exchange made it difficult to maintain and prepare for production.

Currently leading the technical review and phased modernisation of a Python and React dashboard that gives stakeholders a view of application infrastructure from ServiceNow. The work is replacing a large, tightly coupled script and spreadsheet-based configuration with a structured backend and REST APIs. The React application and Python API are now deployed on Rancher; further data-pipeline work is ongoing.

  • Architecture review
  • Python / React
  • REST APIs
  • Rancher
Implementation notes +

After reviewing the codebase with its developer, I broke the work into phases: separate frontend and backend responsibilities, restructure the Python code, remove spreadsheet dependencies, and replace direct consumption of generated JSON files with REST endpoints. The planned next stage uses Prefect flows to collect data into SQL, with the Python API serving it to React.

AI adoption & production delivery

AI adoption and
production delivery.

An existing PDF clause-extraction application had a Python RAG backend and React interface, but needed substantial code and deployment improvements before it could run reliably in production.

I reworked configuration and hardcoded paths, adapted the Tesseract OCR integration for Linux, and brought the application onto GitLab and its CI pipeline. I also changed how the embedding model was packaged for deployment. After resolving application and environment issues, the service was successfully deployed on Rancher and has been running reliably in production for about a year.

  • Python / React
  • RAG
  • Tesseract OCR
  • FAISS
  • GitLab CI
  • Rancher
Implementation notes +

The Python API used RAG, Tesseract OCR, FAISS, and an all-MiniLM embedding model. The model was initially kept directly in the source repository. I changed the container build to retrieve its ZIP artifact from Nexus and include it through the Docker runtime template. Alongside the OCR changes, configuration cleanup, and GitLab CI adoption, I worked through issues across the application and deployment until the production release succeeded.

Recognised in the CIO newsletter for contributions to the clause-extraction application’s production delivery.

Migration tooling & prototypes

Informatica to Python/Prefect

Developed a migration plugin that takes teams from understanding existing Informatica workflows to generating equivalent Python/Prefect implementations. It can work across an application, identifying migration difficulty and common patterns, producing an executive summary, and retaining progress between runs.

  • Informatica
  • Python / Prefect
  • Code generation
  • Agent skills
  • JSON state
Implementation notes +

The plugin separates discovery, assessment and code generation into focused skills. Discovery accepts manual evidence or Informatica XML exports and records missing behaviour and unresolved references. Assessment examines complexity and commonality across workflows. Generated code follows the firm’s Python project structure and AutoSys, Rancher and Prefect conventions. Each skill’s progress is tracked in JSON so the process can continue across runs.

The discovery step keeps extracted metadata, assumptions and missing runtime details explicit. Parameter files, scheduler details, production run history and SME notes provide additional context when available for downstream assessment and code generation.

Prototype

  • Vite

Built the hub with Vite module federation, loading separate microfrontends into a configurable shell. Kubernetes ConfigMaps define the module entries. The skills module retrieves content from GitLab, and the MCP module lists available integrations. I also built the initial reporting module using ServiceNow APIs and other sources; other developers have since extended it.
